# 00. Стенд для VPS / облачных VM

## Что понадобится

Команды рассчитаны на **Ubuntu Server 24.04 LTS с systemd**, Bash и Python 3.12+.
Это целевая ОС курса, а не требование покупать новую VPS. На другом дистрибутиве
отличаются пакеты, имена служб и настройки сети.

| Узел | Назначение | Ориентир ресурсов |
|---|---|---|
| `app` | Учебный сервис, Nginx, затем Docker | 1–2 vCPU, 2 ГБ RAM, 20 ГБ диска |
| `mon` | Prometheus, Grafana, Alertmanager, затем Loki | 2 vCPU, 4 ГБ RAM, 25 ГБ диска |

Это ориентиры для небольшого стенда с коротким хранением данных. Для kind в лабе 13
освободи ресурсы `mon`, временно остановив Loki/Alloy/Grafana; при нехватке RAM
выполни эту лабу на отдельной временной VM или локально. Не запускай нагрузку
одновременно с кластером. Размеры VM и стоимость выбираешь у своего провайдера;
курс не требует платных managed Kubernetes, DNS-зон и балансировщиков.

## Сеть

Предпочтительный вариант — приватная сеть между VM. Адреса ниже **условные**:
подставь реальные адреса из панели провайдера, не назначай их вслепую через Netplan.

```text
Твой компьютер ── SSH ── app  (пример private IP 10.20.0.10)
              └─ SSH ── mon  (пример private IP 10.20.0.20)

mon / Prometheus ── private network ── app:8080 /metrics, app:9100
браузер ── SSH-туннель ── mon:3000 / Grafana
```

Если приватной сети нет, не открывай метрики в интернет. Из `mon` сделай SSH-туннель
к `app`, например локальные `18080 → app:8080` и `19100 → app:9100`. Тогда targets
на `mon` будут `127.0.0.1:18080` и `127.0.0.1:19100`. На `app` процессы могут
оставаться на loopback. В лабе 03 проверишь туннель, а в лабе 10 автоматизируешь его
как службу. Для обратной доставки логов из `app` в `mon` в лабе 09 нужен свой
туннель. Выбери один вариант и внеси адреса в отчёт.

## Порядок подготовки

1. Проверь SSH по ключу на обе VM, `sudo` и доступ к консоли восстановления
   провайдера. Используй учебные машины без рабочих данных.
2. В firewall провайдера разреши SSH только со своего адреса. Для туннелей между VM
   дополнительно разреши SSH с адреса второй VM. Проверь правила IPv4 **и IPv6**.
3. UI Prometheus/Grafana/Alertmanager/Loki оставь на loopback. На приватном интерфейсе
   `app` разреши 8080 и 9100 только от `mon`; HTTP/TLS 80/443 — от своего компьютера
   и нужных учебных узлов. Порт 8080 понадобится только до перехода к proxy.
4. Сохрани текущие правила firewall. Изменяя их, держи открытый SSH-сеанс и проверяй
   новый вход во втором окне. Не меняй SSH и маршрут по умолчанию ради инцидента.
5. Проверь `timedatectl`: время синхронизировано, в отчётах используй UTC.
6. Скопируй репозиторий в `~/devops` на обеих VM. В командах курса это корень проекта.

На обеих VM установи базовые инструменты:

```bash
sudo apt update
sudo apt install -y python3 curl jq git iproute2 dnsutils tcpdump netcat-openbsd \
  sysstat lsof openssl ca-certificates
```

Дополнительные компоненты ставь по мере прохождения, по официальным инструкциям
конкретной лабы. Фиксируй версии в отчёте; контейнерные теги и версии провайдеров
закрепляй, чтобы повторный запуск не зависел от `latest`.

## Первая проверка приложения

На `app`:

```bash
cd ~/devops
python3 labs/_shared/ops-demo/app.py
```

Во втором SSH-сеансе к `app`:

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/readyz
curl -fsS http://127.0.0.1:8080/items
```

Ожидаются 200 и JSON. Останови приложение через Ctrl+C: дальше оно будет запускаться
под systemd. На своём компьютере можно открыть UI через туннель:

```bash
# labuser и MON_PUBLIC_IP замени своими значениями; команда остаётся работать.
ssh -N -o ExitOnForwardFailure=yes -L 13000:127.0.0.1:3000 labuser@MON_PUBLIC_IP
```

После установки Grafana браузер открывает `http://127.0.0.1:13000`.

## Приёмка

- Зафиксированы ОС, ресурсы, адреса, путь до репозитория и схема разрешённых портов.
- Обе VM доступны по SSH, время синхронизировано, ручной запуск API проверен.
- UI и метрики не доступны с посторонних публичных адресов, в том числе по IPv6.
- Знаешь, как остановить учебные процессы и удалить созданные ресурсы. Снимки,
  диски и зарезервированные IP могут оставаться платными после выключения VM:
  проверяй список ресурсов у своего провайдера.

[Ubuntu networking](https://ubuntu.com/server/docs/how-to/networking/).
