# DevOps labs

Практика после основ Linux: один учебный HTTP-сервис, две VPS и серия инцидентов.
Начинай с [подготовки стенда](labs/00-stand/README.md), затем проходи лабы по порядку.
Навигация, базовые команды и права файлов отдельно не повторяются.

[Старый раздел основ Linux](labs/01-linux/README.md) сохранён.

## Как работать

1. Прочитай цель, подготовку и критерии приёмки конкретной лабы.
2. Сделай рабочее состояние и сохрани конфиги. Затем вводи по одной неисправности.
3. Для каждого сбоя запиши: симптом → гипотеза → проверка → причина → исправление.
4. Подтверди восстановление HTTP-проверкой и метриками; одного `active (running)` мало.
5. Заполни [шаблон отчёта](templates/lab-report.md) в `solutions/NN-name/`.

Готовых unit-файлов, Dockerfile, playbook и pipeline здесь нет: их написание — часть
заданий. [Учебное приложение](labs/_shared/ops-demo/README.md), тесты и набор логов
даны, чтобы заниматься эксплуатацией, а не разработкой API.
