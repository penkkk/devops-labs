# 05. Мониторинг: Prometheus, Grafana и проверенные алерты

**Время:** 5–8 часов. **Перед началом:** лабы 02–04, `mon` видит API выбранным способом.

## Цель

Собрать метрики инфраструктуры и приложения, объяснить графики и проверить,
что мониторинг обнаруживает настоящий сбой и замечает восстановление.

## Подготовка

На `app` и `mon` установи Node Exporter, на `mon` — Prometheus, Alertmanager и Grafana.
Выбери пакет или официальный бинарный релиз и запиши версию. До Docker-лабы используй
systemd. Для бинарных релизов проверь checksum и создай отдельных пользователей.
UI слушают loopback, Node Exporter доступен только `mon` или через SSH-туннель.
В Grafana входи через SSH-туннель, задай собственный пароль администратора.

Назови jobs `ops-demo`, `node-app`, `node-mon`, `prometheus`. Target API — `/metrics`
на `app:8080` или `mon:18080` при туннеле. Node Exporter по умолчанию использует 9100;
проверь фактический bind. Для туннеля к `app` используй локальный 19100 на `mon`.
Scrape и evaluation interval для стенда — 15 секунд, retention — 24 часа;
дополнительно ограничь размер хранилища в пределах свободного диска.

## Задания

1. Напиши `prometheus.yml`; проверь `promtool check config`, затем Targets и `up`.
   Докажи, что собираются оба хоста и API. Недоступный target и отсутствующий target
   в конфиге — разные случаи: сравни их в запросах.
2. Создай ограниченный генератор: максимум 1 запрос/с в течение 3 минут,
   `curl --max-time 4`. Последовательно дай обычные ответы, `/fail`, `/slow?ms=700`.
   Генерируй запросы с `mon` выбранным сетевым путём. Не используй бесконечную нагрузку.
3. Напиши PromQL для CPU busy %, доступной RAM %, свободного места % и inode %
   корневой FS. Для файловых систем исключи tmpfs/служебные mounts, проверь labels
   `instance`, `mountpoint`, `fstype`, чтобы случайно не сложить разные диски.
4. Построй RED для приложения: requests/sec, доля 5xx и p95 длительности в секундах.
   Используй `rate()` counter и histogram buckets. В RED исключи `/healthz` и
   `/readyz`; `/metrics` приложение уже исключает. Не усредняй p95 нескольких route:
   сначала агрегируй bucket с сохранением `le`, затем вычисляй квантиль.
5. Собери Grafana dashboard: hosts, RPS, errors, p95, состояние targets. Укажи
   единицы, осмысленные legend и диапазон времени. Экспортируй JSON дашборда.
6. Напиши три алерта с labels severity и annotations с первой диагностической командой:

   | Алерт | Условие для учебного стенда | Как проверить |
   |---|---|---|
   | TargetDown | `up{job="ops-demo"} == 0` в течение 1 минуты | Остановить API, затем вернуть |
   | HighErrorRate | Доля 5xx > 10% за 2 минуты, минимум 0.1 req/s, `for: 1m` | `/fail` раз в секунду 3 минуты |
   | HighLatency | p95 > 0.5 с за 2 минуты, минимум 0.1 req/s, `for: 1m` | `/slow?ms=700` раз в секунду 3 минуты |

7. Свяжи Prometheus с Alertmanager. Проверь pending → firing → resolved.
   Для доставки достаточно локального webhook-приёмника на `mon` с JSON-журналом
   и `send_resolved: true`. Внешние Telegram/email необязательны.
8. На время закрой именно путь scrape. Сравни «сервис умер» и «Prometheus не видит
   живой сервис». Добавь отдельный сценарий удаления target из конфига: почему
   проверка только `up == 0` не обнаружит отсутствующую series? Предложи `absent()`
   или контроль ожидаемого набора targets.

## Приёмка и что сдать

- Конфиги, версии, JSON дашборда и собственные PromQL с объяснением labels.
- Все targets `UP` в штатном состоянии; на графиках видны три режима нагрузки.
- Для трёх алертов есть время начала условия, firing и получения resolved.
- Rule-файл проходит `promtool check rules`; для одного алерта написан и выполнен
  `promtool test rules` с нормой, сбоем и восстановлением.
- UI и exporters закрыты от посторонних; накопленные данные укладываются в лимит.

## Контрольные вопросы

1. Чем counter отличается от gauge, и почему `rate()` переживает restart counter?
2. Почему при отсутствии запросов доля ошибок может стать NaN, а не нулём?
3. Почему `request_id` в metric labels опасен для числа временных рядов?
4. Почему `up=1` не доказывает успешность `/items`?
5. Чем `for` отличается от окна `[2m]`, а Alertmanager — от вычисления alert rule?
6. Что означает p95 при нескольких запросах в минуту и грубых histogram buckets?

Подсказки: сначала посмотри сырые `/metrics` и labels, затем строй выражение.
Используй минимум трафика для rate-алертов; проверяй окно после двух и более scrapes.
