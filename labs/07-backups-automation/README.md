# 07. Автоматизация Bash и восстановление из бэкапа

**Время:** 4–6 часов. **Перед началом:** лабы 02–06.

## Цель

Написать обслуживающий скрипт с предсказуемыми ошибками и проверить восстановление
данных. Результат — восстановленный сервис, а не просто созданный архив.

## Задания

1. Напиши `check-service.sh URL`: connect/total timeout, проверка HTTP status,
   UTC-время, длительность и понятный exit code. Отличай transport error от HTTP 503.
   Не печатай секреты из URL. Скрипт должен работать и при URL без query string.
2. Напиши `backup.sh`: сохранять `/var/lib/ops-demo/items.json`, конфиги API и Nginx,
   список версий и commit. Учебный TLS-ключ, если нужен для полного восстановления,
   хранить только в закрытом архиве с правами 0600, не в отчёте/Git.
3. Добавь lock от параллельного запуска, проверку входных файлов, временный файл
   и атомарное переименование готового архива. Не удаляй старую копию до успешного
   создания новой. Рассчитай checksum; запись «успешно» возможна только после всех проверок.
4. Храни последние 3 успешных копии. Копируй архив на `mon` по отдельному SSH-ключу
   с минимальными правами. Это учебная защита от потери `app`, а не полноценная
   географически независимая стратегия бэкапа.
5. Напиши service типа oneshot и timer с ежедневным расписанием и `Persistent=true`.
   Проверь ручной старт, следующий запуск и журнал ошибки. Зафиксируй timezone
   расписания; не полагайся на timezone своей рабочей станции.
6. Сделай backup, затем измени или испорти **только учебный** `items.json`.
   Восстанови в отдельный staging-каталог, проверь checksum, список файлов и JSON.
   Сохрани повреждённую версию для анализа; затем подмени рабочую копию и проверь
   владельца, `/readyz` и `/items`.
7. Измерь фактический RPO и RTO эксперимента. Повтори восстановление на пустом
   каталоге без использования исходных файлов `app`.

## Инциденты

- Нет места в каталоге назначения: смоделируй недоступный каталог либо ограниченную
  отдельную FS; архив не должен считаться успешным.
- Вторая копия скрипта запущена одновременно: одна получает понятный отказ по lock.
- Повреждён архив: checksum не сходится, рабочие данные не перезаписываются.
- `mon` недоступен: локальный backup не выдаётся за успешную внешнюю доставку;
  определён код ошибки и порядок повторной попытки без удаления последней внешней копии.

Дополнительно: создай файловый образ максимум 64 МБ в учебном каталоге, отформатируй
и смонтируй через loop, заполни **только эту FS**. Подтверди ENOSPC через `df` и логи,
затем размонтируй и удали образ. Не добавляй его в fstab, не выбирай `/dev/sdX`.
Если loop/mount запрещены провайдером, пропусти этот эксперимент и укажи ограничение.

## Приёмка и что сдать

- Скрипты, unit/timer, `bash -n`; ShellCheck, если установлен, без необъяснённых ошибок.
- Коды выхода для нормы, сбоя API, ошибки архива и внешней доставки проверены.
- В отчёте содержимое восстановленных данных, время восстановления и потерянные изменения.
- Повреждённый архив не затёр рабочий сервис; retention сохранил последние успешные копии.
- Секреты и сами архивы исключены из Git. Любые временные mounts удалены.
