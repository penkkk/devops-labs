# 10. Ansible: сервер можно настроить повторно

**Время:** 4–6 часов. **Перед началом:** лабы 02–09; рабочие конфиги сохранены в Git.

## Цель

Перевести ручную настройку в проверяемые роли и получить предсказуемый повторный
запуск. Ansible настраивает ОС и службы, Compose описывает контейнерный стек.

## Задания

1. Выбери control node: свой компьютер или `mon`. Настрой inventory с группами
   `app` и `monitoring`, отдельного SSH-пользователя, host key verification и
   `become` только для задач, которым нужны права. Проверь модуль `ping`.
2. Создай роли `common`, `app_stack`, `monitoring`. Для начала автоматизируй пакеты,
   каталоги с точными владельцами, конфиги, Node Exporter, journal limits и Compose
   проекта. Не переписывай firewall и SSH вслепую: параметры бери из схемы стенда.
3. Преврати переменные адреса, порты и digest приложения в group_vars/host_vars.
   Конфиги формируй шаблонами; restart/reload выполняй handlers только при изменении.
   Для Compose используй соответствующий модуль коллекции с закреплённой версией
   либо явно объясни идемпотентность выбранного способа.
4. Для варианта без private network добавь отдельную службу SSH-туннелей,
   ограниченные ключи и проверку host keys. При restart службы локальные listeners
   должны возвращаться. Не используй `StrictHostKeyChecking=no`.
5. Пароль Grafana и ключи не храни открытым текстом. Используй Ansible Vault либо
   внешний secret store; vault password держи вне репозитория. Diff/no_log настрой
   так, чтобы секреты не попадали в вывод. Шифрование файла не заменяет права доступа.
6. Выполни syntax-check и check/diff mode. Укажи, какие задачи не поддерживают
   полноценный dry run. Применяй по одному узлу, затем повтори тот же playbook:
   ожидается `changed=0`, если входные данные и состояние не изменились.
7. Измени копию конфига вручную и верни её playbook. Обнови версию API через
   переменную, проверь health и при неуспехе откатись на прежний digest.
8. Проверь воспроизводимость на временном чистом учебном узле, если он уже есть.
   Без дополнительной VM восстанови только созданные курсом каталоги/конфиги из
   контролируемого состояния и явно укажи, что полноценная проверка clean VM
   не выполнена. Не удаляй системные каталоги и Docker глобально.

## Инциденты

- Неверный inventory host: ошибка соединения должна быть отделена от ошибки задачи.
- Шаблон Nginx синтаксически неверен: validation блокирует установку/reload.
- API после deploy не ready: playbook завершается ошибкой, известен способ отката.
- Handler перезапускает сервис на каждом прогоне: найди задачу с ложным `changed`.

## Приёмка и что сдать

- Inventory без секретов, роли, шаблоны, закреплённые зависимости и инструкция запуска.
- Второй прогон без изменений, отчёт dry run и восстановление ручного drift.
- HTTP-проверка является частью playbook; failed deploy не считается успешным.
- Логи не раскрывают секреты, host key verification включена.
- Чётко указано, проверялся ли bootstrap на чистой VM.
