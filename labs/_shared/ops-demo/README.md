# ops-demo: общий сервис для лабораторных

Python 3.12+, только стандартная библиотека. Это учебный сервер с намеренно
доступными endpoint для ошибок и задержек; держи его в закрытом стенде.

```bash
# Из корня репозитория; запуск не меняет систему и не требует root.
python3 labs/_shared/ops-demo/app.py
python3 -m unittest discover -s labs/_shared/ops-demo -p 'test_*.py' -v
```

| Настройка окружения | По умолчанию | Назначение |
|---|---|---|
| `APP_HOST` | `127.0.0.1` | IPv4-адрес прослушивания |
| `APP_PORT` | `8080` | TCP-порт |
| `APP_VERSION` | `dev` | Версия в JSON-ответах |
| `DATA_DIR` | `data` рядом с `app.py` | Каталог с `items.json` |

| Запрос GET | Результат |
|---|---|
| `/` | 200, версия приложения |
| `/healthz` | 200, процесс отвечает; состояние данных не проверяется |
| `/readyz` | 200 при читаемом корректном `items.json`, иначе 503 |
| `/items` | 200 и JSON-массив из `items.json`, иначе 503 |
| `/fail` | Контролируемый 500 |
| `/slow?ms=700` | 200 после 700 мс; допустимо 0–2000 мс, иначе 400 |
| `/metrics` | Prometheus text format; запросы сюда не учитываются в бизнес-метриках |
| Остальное | 404; в метриках route=`other` |

Создание файла `DATA_DIR/not-ready` переводит `/readyz` в 503, не останавливая
процесс и не меняя `/healthz`. Удаление файла возвращает readiness, если данные
исправны. `/items` при этом продолжает читать данные — это отдельный сигнал
готовности, который должен учитывать балансировщик.

Приложение **только читает** `items.json`; запись данных и база здесь не реализованы.
Для лабы восстановления достаточно менять учебный JSON-файл вручную. Код, runtime
данные и конфиги при установке разнеси по `/opt/ops-demo`, `/var/lib/ops-demo` и
`/etc/ops-demo` соответственно. Приложение запускай отдельным пользователем `opsdemo`.

stdout содержит JSON Lines: `ts`, `level`, `event`, `request_id`, `method`, `path`,
`status`, `duration_ms`, `version`. Для сквозного поиска принимается заголовок
`X-Request-ID` из 1–64 латинских букв, цифр, `_` и `-`; иначе создаётся новый ID.
Ответ возвращает тот же ID. Query string и тела запросов в журнал не пишутся.
При ошибке чтения данных поле `error` содержит тип ошибки без содержимого файла.
Успешный scrape `/metrics` не логируется, чтобы не засорять журнал.

Метрики бизнес-запросов:

- `ops_demo_http_requests_total{route,status}` — counter.
- `ops_demo_http_request_duration_seconds_bucket{route,le}` и `_sum`, `_count` — histogram.

Counter сбрасывается при перезапуске процесса. Значения bucket накопительные.
`request_id`, IP и произвольные URL не используются как labels. Это позволяет
отдельно изучить корреляцию логов и кардинальность метрик.
